## 외형 자산 규격 (B용)

- `renderUrl`: 256×256 PNG, 투명 배경, 흰 스티커 외곽선. 캐릭터는 하단 중앙에 선다. 그림은 그린 영역만 잘라 맞추고, 사진은 원형이다.
- `originalUrl`: 그림은 512×512 투명 PNG, 사진은 사용자가 넣은 파일 그대로다.

**그림 경로:** 캔버스에 그린 뒤 저장 → 서버의 render/original을 브라우저에서 디코드해 크기·형식·그린 색 픽셀 확인 → 새 탭 재진입 복원 → 외형을 그대로 재저장해 같은 assetId 유지 확인.

**사진 경로:** 잘못된 파일, 손상된 PNG, 8MB 초과를 각각 거부 → JPEG 입력 → 드래그로 크롭 이동 → render에 크롭 결과가 반영되고 original은 800×400 JPEG 그대로임을 픽셀로 확인 → 재진입 복원.

**교실 반영 (임시 조합, 커밋 대상 아님):** 스크래치 복사본에 C 커밋, B·E의 당시 미커밋 작업 트리를 합쳐 실행했다. B의 테스트 훅과 캡처 양쪽에서 그림과 사진이 각각 플레이 캐릭터로 나타나고, 사진 경로는 페이지를 새로고침해도 유지됨을 확인했다. **통합 커밋에서의 확인이 아니므로 A/F가 다시 확인해야 한다.**

참고: root e2e와 C e2e는 `.next-e2e`를 공유한다. 오래된 캐시가 남으면 페이지가 계속 다시 로드되어 root 스모크가 실패한다(1회 재현, 캐시 삭제로 해소). C 설정은 시작 시 비우지만, C e2e 뒤에 root e2e를 돌릴 때는 `rm -rf .next-e2e`가 필요하다.

## F용 testid

요청 이름을 그대로 사용했다. 위치만 참고한다.

- `model-option-<modelId>`: 카드의 선택 버튼 (카드 자체는 `data-model-id`)
- `avatar-mode-drawing`, `avatar-mode-photo`: 라디오의 label

기반 스모크가 쓰는 `에이전트 없이 교실 보기` 링크는 저장된 에이전트가 없을 때만 보인다. 있으면 `저장된 <이름>(으)로 교실 가기`다.

## A에게 요청

병합에 필요한 공통 변경은 없다. `3da15f3`은 C 파일을 건드리지 않아 이 브랜치에 반영하지 않았다.

1. **B 조정 필요:** 임시 조합에서 B의 사진용 세로 카드가 원형 render의 좌우를 잘라 표시했다. render는 이미 스티커 형태이므로 추가 프레임 없이 그대로 쓰거나, 사각 render가 필요하면 C에게 요청해 달라.
2. **재진입 경로(선택):** 교실에 프로필 수정 링크가 없다. 지금은 로고 → 소개 → 입장으로만 돌아온다. `ClassroomScreen`에 `/create` 링크를 권한다.
3. **모델 준비 계약:** 모델로 기존 준비 작업을 찾는 조회가 없어 재진입 시 준비 상태를 복원하지 못하고 다시 요청할 수 있다. E의 `createModelPreparation`이 같은 모델 요청을 중복 처리하지 않는지 확인하거나 조회 계약을 추가해 달라.
4. **공급처 필터:** `CatalogSearchQuery.source`에 쓸 공급처 목록 계약이 없어 값을 지어내지 않고 필터를 만들지 않았다. E가 공급처를 늘리면 목록 API가 필요하다.

## 남은 사항

- 사진 원본은 입력 파일 그대로 저장되어 EXIF(위치 정보 포함 가능)가 남는다. 조회는 익명 소유자 쿠키로 제한되지만, 공유 기능이 생기면 제거가 필요하다.
- 직접 그리기는 포인터 입력 전용이다. 키보드 사용자는 사진 경로를 쓴다.
- 모델 준비의 실제 동작과 통합 커밋에서의 교실 반영은 E·B 병합 후 확인이 필요하다.
