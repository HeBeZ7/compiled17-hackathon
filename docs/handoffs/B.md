## 변경 파일

모두 `src/features/classroom/**` 안이다.

- `movement.ts`, `world.ts`: 순수 이동·충돌 로직과 교실 배치. 충돌과 미술이 같은 수치를 쓴다.
- `input.ts`: 키보드·방향패드 병합, 이동 정지 규칙. Phaser 키보드는 쓰지 않는다(상담 입력의 WASD를 가로채지 않도록).
- `ClassroomScene.ts`, `Classroom.tsx`, `DirectionPad.tsx`: 게임 장면과 `ClassroomProps` 구현.
- `art/*`: Canvas 2D로 그린 자체 교실·가구·캐릭터. 외부 이미지 자산은 쓰지 않아 `public/assets/classroom/`은 비어 있다.
- `testHook.ts`: `NEXT_PUBLIC_AA_TEST_MODE === "1"`에서만 불리는 E2E 관측 훅.

### 동작 메모

- 상호작용 키는 **E, Enter, Space**이고, 화면 버튼도 함께 표시된다.
- 이동 속도는 Phaser의 평활화 delta가 아닌 실제 경과 시간을 쓴다. 평활화 delta를 쓰면 저사양 환경에서 슬로모션이 되는 것을 실측으로 확인했다.
- 외형: 그림은 실루엣을 유지한 스티커, 사진은 C의 렌더(투명 배경 원형 스티커)를 자르지 않고 비율을 유지해 그대로 세운다. 걸을 때 몸체를 기울이고 발을 움직인다. 방향별 그림 생성은 하지 않는다. 사진을 좌우 반전하지 않는다.
- 외형 로드 실패 시 기본 캐릭터로 표시하고 교실 안에 오류를 보여 준다. 에이전트가 없으면 이름표에 `개발용 임시 캐릭터`로 표시한다.
- 좁은 화면(폭 720px 이하, 또는 교실 전체를 읽기 어려운 배율)에서는 카메라가 캐릭터를 따라간다.

### F 스펙 실패 2건

- **C9**: `teacher-input` testid가 없어 시간 초과. D의 상담 입력창이 통합되어야 실행된다. B 결함은 아니다. 같은 동작(패널 입력 중 이동 없음, WASD 입력됨)은 앱 시나리오에서 A의 현재 패널로 확인했다.
- **C3 대각선 속도**: 재실행 6회 중 3회 실패. 결정적 비교(단위 테스트)와 5회 중앙값 비교는 통과했다. 500ms 측정에 약 12fps면 프레임 하나의 오차가 약 ±0.04px/ms라 임계 1.15배를 넘을 수 있다. 실패 때 직선이 낮게 측정되고 대각선 평균은 설계 속도(0.25)와 맞는다. 측정 방식 조정(더 긴 측정 또는 중앙값)은 F가 판단한다. 실제 GPU 환경에서는 미실행이다.

### 사진 외형 좌우 잘림 수정 (통합 커밋 `b6ad9a7` 병합 후)

`paintAvatarStandee`의 사진 분기가 cover 배율과 카드 클립으로 렌더 좌우를 잘랐다. contain 배율(`Math.min`)로 렌더 전체를 `footX/footY`에 세우고 카드 테두리를 없앴다. 그림 분기와 함수 시그니처는 그대로다.

- `npm run verify`: 통과 (vitest 177건 통과, 33건 건너뜀).
- 실제 앱 3001 테스트 모드, headless Chromium(소프트웨어 WebGL), 1440x900: `POST /api/avatars` → `PUT /api/agents/current` → `/classroom`에서 `ready()` 후 플레이어 화면 픽셀 측정. 합성 256x256 PNG 두 종(좌우 끝 16px 마젠타/초록인 정사각형, C의 사진 렌더와 같은 형태의 투명 배경 원형 스티커)으로 실행했다.
- 정사각형: 좌우 색 모두 보임. 바깥 경계 월드 x 8.27 / 104.26(예상 8 / 104), 색 띠 폭 6.07(예상 6), 표시 영역 174x174 기기 픽셀로 비율 유지.
- 원형 스티커: 좌우 색 모두 보임. 바깥 경계 11.58 / 100.95(예상 11 / 101).
- 대조: 같은 스크립트를 수정 전 코드로 돌리면 정사각형의 좌우 색이 0픽셀이다(잘림 재현).

업로드는 API를 직접 호출했다. C의 사진 입력 화면에서 시작하는 전체 경로는 이번에 미실행이다. 스크립트는 저장소에 넣지 않았다(스크래치 경로).

## 실제 / 대역 / 미연결

- **실제 동작:** 이동, 충돌, 입력 정지, 근접, `onInteract` 호출(실제 앱 셸 연결 확인).
- **대역:** 없음. 외형 검증은 하네스에서 data URL 이미지를 `AgentProfile` 형태로 넣어 실행했으며 제품 코드에는 대역이 없다.
- **미연결·미실행:**
  - C의 실제 업로드 → `renderUrl`로 교실에 표시되는 end-to-end 경로
  - 실제 GPU·실제 터치 기기·Safari(바닥 빛 흐림에 쓰는 `ctx.filter` 미지원 시 경계가 또렷해지는 것으로 설계, 미확인)
  - 실제 창 전환(합성 blur로 검증)
  - **수정된 밝은 교실 기준 이미지와의 비교.** 이미지를 받지 못해 `ART_DIRECTION.md` 글 기준으로만 제작했다.

## A에게 필요한 사항

1. **`next.config.ts`에 기본값 추가 요청.** `env: { NEXT_PUBLIC_AA_TEST_MODE: process.env.NEXT_PUBLIC_AA_TEST_MODE ?? "0" }` 해당 값이 빌드 시 미정의면 Next가 상수로 치환하지 않아 훅이 2KB 청크로 번들에 남는다. 실행 시에는 로드되지 않고 `window.__AA_TEST__`도 없음을 확인했다. 값을 `0`으로 명시한 빌드에서는 번들에서 사라짐을 확인했다.
2. `npm run build`를 `AA_DIST_DIR`로 새 경로에 실행하면 Next가 추적 파일 `tsconfig.json`을 다시 쓴다. 이번에는 되돌렸다. 필요하면 `.next-*/types`를 include 패턴으로 일반화하는 것을 검토한다.
3. 통합 시 `Classroom`의 임시 버튼(`선생님에게 말 걸기`, `학습 자리 열기`)과 `classroom-placeholder` testid가 사라진다. 교실 진입 후에는 이동해 다가가거나 E를 눌러 연다.

타입·의존성·전역 토큰 변경 요청은 없다. 이번 브랜치는 A의 `ClassroomProps`와 CSS 토큰을 그대로 사용한다.
